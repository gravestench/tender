# US ACH debit qualification

Updated 2026-11-24. The reference route is Adyen Checkout v72 Sessions with Adyen Web 6.45.2 and giact consumer ecommerce for one-time US/USD WEB debits. Its test browser submits account fields to Adyen, while Go receives session and projected payment evidence. The pinned ACH component uses same-origin inputs, so merchant JavaScript can technically read bank values; this probe checks that its own script does not intentionally log, retain or send them to the host. A provider/ODFI-approved consent and data-retention design remains an external G4 gate. MOCK contracts exercise authorization, a signed failure hold, settlement, return after settlement, report matching, lost response and idempotent replay. Official ACH compatibility is **BLOCKED**.

| Scenario | Local observation | Official merchant observation |
| --- | --- | --- |
| Bank entry and consent | Synthetic browser component stays on page and the host receives no bank account/routing field. | **BLOCKED:** ACH/giact enrollment, registered origin, credentialed browser transport and a merchant-approved signed mandate presentation/retention design. |
| Debit and refusal | The fixture reports pending authorization or refusal; signed correlated failure creates a review hold. | **BLOCKED:** actual provider test debit, giact validation outcome and generated signed receipt. |
| Settlement and return | Signed/host-authenticated projected evidence can record gross settlement and later return without erasing collection history. | **BLOCKED:** genuine settled and returned test debit, corresponding Standard events and Settlement details report. |
| Bank reach and price | ACH network routing can cover eligible personal bank/credit-union accounts through the provider. | **BLOCKED:** account-specific acceptance, fee quote and actual net payout. |

`TestACHSandboxSessions` uses the `sandbox` build's test-only `NewACHSandboxQualification` constructor, then the same ACH adapter and `Engine.Create`/`Engine.Confirm` path against Adyen's exact test v72 endpoint. The ordinary `NewACH` constructor still disables SANDBOX and LIVE, and the qualification constructor rejects injected transports, clocks, mock URLs and LIVE configuration. The browser gate also rejects loopback and reserved mock origins. The pinned browser submits bank fixtures only to Adyen and passes the opaque `sessionResult` to Go in memory. `TestACHSandboxReport` compares exported host identity with two provider CSV rows; each host-authenticated Settlement details row must include a `Booking Date (AMS)` within 30 days. CI file creation time is not freshness evidence. Both tests end in visible **BLOCKED** because they do not yet correlate one durable host payment with an approved signed mandate, genuine provider event, complete authenticated settlement/return report and same-order browser proof. Follow [the ACH setup guide](../providers/ach.md) and [partner decision](../adr/0005-us-ach-partner.md). Record merchant, UTC time, API/SDK version, consent version, device, expected/observed status, sanitized PSP/modification references, amount and bank deposit evidence. Never record bank numbers or account holder personal data.
